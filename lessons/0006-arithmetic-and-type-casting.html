What this chapter introduces

Rust supports familiar arithmetic operators—+, -, *, /, and %—but it will not silently mix incompatible numeric types. An i64 and an f64 cannot be divided until you explicitly make them the same kind of number.

You will also reuse Day 5’s input pattern. Terminal input is text, so trim().parse() converts clean numeric text into the integer type you choose.

Course source: Tech With Tim’s Rust Programming Tutorial.

Five arithmetic operators

Add+8 + 3 is 11.
Subtract-8 - 3 is 5.
Multiply*8 * 3 is 24.
Divide/Its result type follows its operands.
Remainder%95 % 7 is 4.
Numeric literal95A number written directly in code. A suffix such as 7_i64 states its type.
The important division rule: 95_i64 / 7_i64 is 13, because integers cannot store the fractional part. 95.0_f64 / 7.0_f64 is about 13.5714, because floating-point values can.

Choose the conversion deliberately

as performs an explicit numeric cast. It tells Rust that you intend to convert a value before the calculation:

let whole_minutes: i64 = 95;
let days: i64 = 7;

let whole_average = whole_minutes / days;             // 13
let precise_average = whole_minutes as f64 / days as f64; // 13.571...

For an operation, make both operands compatible. Casting a smaller integer type to a larger one before arithmetic often preserves more possible values. Casting from a larger integer type to a smaller one can discard information, so do not use as as a casual fix for a type error.

In this lab, the cast is safe for the purpose at hand: every i64 value can be represented as an f64 magnitude, although very large integers may lose exact one-unit precision. We only need a readable decimal average.

Replace src/main.rs with this program, then save:

use std::io;

fn main() {
    println!("How many minutes did you study this week?");

    let mut input = String::new();
    io::stdin()
        .read_line(&mut input)
        .expect("Failed to read line.");

    let weekly_minutes: i64 = input
        .trim()
        .parse()
        .expect("Please enter a whole number.");
    let days: i64 = 7;

    let whole_daily_average = weekly_minutes / days;
    let remainder = weekly_minutes % days;
    let precise_daily_average = weekly_minutes as f64 / days as f64;

    println!("{weekly_minutes} minutes over {days} days:");
    println!("Whole-number daily average: {whole_daily_average}");
    println!("Precise daily average: {precise_daily_average}");
    println!("Minutes left after equal whole-minute days: {remainder}");
}

Format and run it:

cargo fmt && cargo run

Enter 95. The whole-number average should be 13, the remainder should be 4, and the precise average should begin 13.5714.

Read the result: two real runs

The calculator separates a division into three useful views. The relationship is always weekly_minutes = (days × whole_daily_average) + remainder.

Input16 minutes16 = (7 × 2) + 2.
Result2, 2, 2.285714…Whole average, remainder, then precise average.
Input95 minutes95 = (7 × 13) + 4.
Result13, 4, 13.571428…Integer division drops the fraction; decimal division retains it.
95 minutes over 7 days:
Whole-number daily average: 13
Precise daily average: 13.571428571428571
Minutes left after equal whole-minute days: 4

The difference is not an arithmetic mistake. 95_i64 / 7_i64 has an integer result, so it keeps only 13. After conversion, 95.0_f64 / 7.0_f64 can represent the fractional part.

Make Rust catch a mixed-type calculation

After the successful run, temporarily remove only the first cast:

// Temporarily broken: i64 divided by f64

Save and run cargo fmt && cargo run. Rust should say there is no implementation for i64 / f64. Restore weekly_minutes as f64 and rerun. Rust needs both operands to have compatible types; the intended decimal calculation is f64 / f64, not an automatic mixture of an integer and a float.
