What this chapter introduces

A condition is an expression that becomes true or false. Rust can compare values with <, <=, >, >=, ==, and !=; the values on both sides must have compatible types. Use && for “and”, || for “or”, and ! for “not”.

An if checks its condition. If it is false, Rust tries each else if in order, then falls back to else. Once one branch runs, the rest are skipped.

Course source: Tech With Tim’s Rust Programming Tutorial.

A small but important Rust rule

2 <= 2.2 does not compile: the left value is an integer while the right is a floating-point number. Make the values the same type before comparing them. In today’s program, the parsed input and every number we compare it with are i32.

Here is the same decision in Python:

if not is_positive:
    print("Start with one small program today.")
elif has_foundation and practice_days < 30:
    print("You have a foundation.")
elif practice_days >= 30:
    print("You have real momentum.")
else:
    print("You are building momentum.")

In Rust, braces mark each block and most statements inside them end with semicolons. The branch logic still reads from top to bottom: the first true branch runs, then Rust skips the rest.

Trace your input: 6

After you changed the foundation threshold to 7, the program checks each branch in order:

  1. !is_positive: is_positive is true because 6 > 0, so !true is false. Skip this branch.
  2. has_foundation && practice_days < 30: the threshold now asks whether 6 >= 7, which is false. Since both sides of && must be true, skip this branch.
  3. practice_days >= 30: 6 >= 30 is false. Skip this branch too.
  4. No condition matched, so the final else runs and prints: “You are building momentum.”

Python’s elif and Rust’s else if mean the same thing: check this next condition only if all earlier conditions were false. The final else is the fallback when none matched.

Read the branches in order

FirstifIs the number zero or negative?
Thenelse ifHas the learner reached six days?
OtherwiseelseGive the early-momentum message.

The “30 days” branch is deliberately after the “six days” branch only if the first condition also limits itself with && practice_days < 30. Branch order matters.
