Where does Rust keep your data?

See the simple difference between stack memory for fixed-size values and heap memory for data that can grow.

25–35 minutesOne small programStack and heap

The big idea

When a program runs, it uses computer memory to keep track of its values. Rust uses two important areas called the stack and the heap. Think of them as two different ways to organize memory—not as the stack and heap data structures from an algorithms class.

For now, remember this simple rule: fixed-size values such as an i32 fit directly into a stack slot. Data that can change size, such as a growable String, uses space on the heap.

This is a teaching picture, not a map of every byte. The important part is that a String has a small, fixed-size handle and separately stored text that can change size.

What is the stack?

The stack keeps track of a function’s active work. Imagine a pile of trays: you put a new tray on top, and you take the top tray off first. In code, each function call gets its own working area. When that function finishes, its area is cleared.

Values such as numbers and bools have a known size, so Rust can give them predictable space. This makes stack storage quick to work with.

What is the heap?

The heap is a more flexible area for data whose size can change. A String can hold a short word now and more text later. Rust asks the memory allocator to find room for those characters.

The String value on the stack keeps a pointer (where the text is), a length (how many characters’ bytes are being used), and a capacity (how much room is available). You do not need to manage those details by hand; Rust’s String type does that work for you.

Finding heap space and following a pointer can take extra work compared with reading a simple stack value. That does not mean you should avoid String. Use the kind of value your program needs; Rust makes both stack and heap storage practical.

Step 1 · one fixed-size value

Put an integer to work

Replace the contents of src/main.rs with this:

fn main() {
    let score: i32 = 95;
    println!("Score: {score}");
}

Run cargo fmt && cargo run. You should see Score: 95. An i32 always has the same size, so it is a good example of a value stored directly in a stack slot.

Step 2 · text that can grow

Add a String

Add these lines inside main, just below the score line:

let language = String::from("Rust");
println!("Language: {language}");
println!("Text length: {} bytes", language.len());

Save and run again. You should see the language and a length of 4. The language variable has a small handle on the stack; its text lives in flexible heap space. String::from makes an owned, growable string from the text.

Change "Rust" to "Rust is fun" and run again. The string now has more text. Its length is measured in bytes; these example characters use one byte each.

When the function is done

At the end of main, its local variables are no longer needed. Rust clears the stack work for that function. The String also takes care of releasing its heap space when it is no longer in use. The next chapter explains the ownership rule Rust uses to know when that should happen.

For now, do not worry about manually freeing memory. Notice that you created and used a growable string, and Rust handles its cleanup.
