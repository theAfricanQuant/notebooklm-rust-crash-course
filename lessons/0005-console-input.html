What this chapter introduces

Until now, every value in your programs came from code you wrote. Today, the program receives a value at run time. Rust’s standard library provides std::io for input and output; stdin() means the terminal’s standard input stream.

Reading a line needs a place to put that text. You will create an empty, mutable String, then pass a mutable reference—&mut name—to read_line so it can fill that same string.

Keep the model simple today: &mut name means “this function may update name.” References and borrowing get a dedicated treatment later; for this lab, recognize the pattern and observe its effect.

use std::io; brings the input/output module into scope. Rust automatically makes a small set of common items available through its prelude, but io is not one of them, so this import is explicit. The double colon :: follows a path: standard library → io module → function or type.

Why Rust asks for mut

String::new() starts with an empty string. The next step changes that same string by adding the line you typed, so the binding must be mutable:

let mut name = String::new();
io::stdin()
    .read_line(&mut name)
    .expect("Failed to read line.");

Rust makes a binding immutable unless you explicitly write mut. Here, name is the name bound to an empty String; read_line needs to put your characters into that existing string. &mut name lends read_line temporary, exclusive permission to update it. Without mut, Rust rejects that request before the program runs.

read_line returns a Result: either the input was read or an error occurred. Calling expect(...) handles the error case by stopping with your helpful message instead of leaving Rust’s “unused result” warning behind. The exact mechanics of Result come later; the important habit now is to handle an operation that can fail.

In the newly opened project, replace src/main.rs with this program and save it:

use std::io;

fn main() {
    println!("What name should I use?");

    let mut name = String::new();
    io::stdin()
        .read_line(&mut name)
        .expect("Failed to read line.");

    println!("Hello, {name}");
}

Back in Zed’s terminal, format and run it:

cargo fmt && cargo run

The terminal will wait after the question. Type a name, press Enter, and look for a greeting containing that name. You may see an extra blank line after the greeting because read_line keeps the Enter newline in the string; that is expected today.

One deliberate break, one useful compiler message

After the successful run, temporarily change let mut name to let name, save, and run the same command again. Rust should explain that it cannot borrow name as mutable. Restore mut, save, and rerun until the greeter works.

What to notice: Rust does not merely say something failed. Its diagnostic points to the binding that needs mut and shows the change it expects. This is the same compiler-guided workflow you used in Day 3.
