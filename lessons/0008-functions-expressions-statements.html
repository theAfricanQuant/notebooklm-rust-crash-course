Teach your Rust code to do a job.

A function is a named job for your program. You’ll give one numbers to work with and get an answer back.

30–40 minutesType each step in ZedFunctions

Today’s idea

A function is a little set of instructions with a name. You can call it whenever you need that job done. In Rust, write fn to make a function. Put the input names and their types in parentheses. Use -> i32 when the function will give back an integer.

Today’s other idea is the difference between a statement and an expression. A statement does something, like make a variable. An expression works something out and has a value. In Rust, the last expression in a function gives back the function’s answer when you leave off the semicolon.

Step 1 · a function with no inputs

Define it, then call it

Replace the contents of src/main.rs with this first version:

fn main() {
    say_hello();
}

fn say_hello() {
    println!("Hello from my own function!");
}

Save and run cargo run. You should see the hello message. Rust starts your program at main. The line say_hello(); tells it to run the instructions inside say_hello. Rust lets you write that function below main. Use lowercase words separated by underscores in function names, like say_hello; Python uses the same style.

Why does println! go inside main?

println! is an instruction to do something: show text on the screen. Rust needs instructions like that inside a function so it knows when to run them. The program begins at main, so we put the print there—or inside another function that main calls.

Also, total only exists inside main because that is where we create it. A print that uses total has to stay there too.

Step 2 · give a function an input

Add a typed parameter

Replace the code with this version. The function now receives a number of practice days:

fn main() {
    show_practice_days(6);
}

fn show_practice_days(days: i32) {
    println!("You practised Rust for {days} days.");
}

Run it, then change 6 to another number. show_practice_days(6) calls the function and gives it the number 6. Inside the function, that number is called days. The part days: i32 tells Rust that days must be a whole number of this type.

In Python, you might write def show_practice_days(days):. Rust asks you to write the input’s type too, so it can catch a wrong kind of input before the program runs.

Step 3 · return a value

Make a function calculate

Now replace it with a function that accepts two numbers and gives their sum back:

fn main() {
    let total = add_numbers(16, 7);
    println!("Together: {total}");
}

fn add_numbers(left: i32, right: i32) -> i32 {
    left + right
}

Run it. You should see Together: 23. The function gets 16 and 7, adds them, and gives 23 back. The arrow -> i32 is its promise: “I will give back an integer.”

Python usually writes return left + right. Rust can do the same job with its last line: left + right. With no semicolon, that line’s answer becomes the function’s answer.

Try adding a semicolon after left + right and run again. The compiler will complain because the function promised an integer but now gives back no answer. Remove the semicolon to fix it.

One line does something; another has an answer

Statement: does a joblet count = 6;Makes a variable called count. This line itself has no answer to hand back.
Expression: works out an answercount + 1Adds one to count. If count is 6, the answer is 7.
Last expression in a Rust functionleft + rightWithout a semicolon, this answer is also the function’s answer.
Return right nowreturn total;Stops the function here and gives back total.

A block can contain statements and finish with an expression:

let next_week = {
    let this_week = 6;
    this_week + 1
};

The first line makes a temporary variable called this_week. The last line adds one and gives the answer to next_week, so next_week becomes 7. That last line has no semicolon. Add one, and the block stops giving back the number.

Python comparison: result = left + right makes a variable, and return result sends its value back to the caller. In Rust, the last line result can send it back without writing return.

Step 4 · add a decision inside a function

Stop early if the goal is reached

Replace the program with this version. It puts yesterday’s if lesson inside a function:

fn main() {
    let total = add_numbers(16, 7);
    println!("Together: {total}");
    println!("Days left until 30: {}", days_until_goal(total, 30));
}

fn add_numbers(left: i32, right: i32) -> i32 {
    left + right
}

fn days_until_goal(current_days: i32, goal: i32) -> i32 {
    if current_days >= goal {
        return 0;
    }

    goal - current_days
}

Run it. You should see Days left until 30: 7. The function checks whether you have already reached the goal. If so, return 0; stops the function and gives back zero right away. Otherwise, the last line subtracts the current days from the goal and gives back the answer.

Try changing the call to days_until_goal(30, 30). Now the goal is already reached, so the answer should be 0.
