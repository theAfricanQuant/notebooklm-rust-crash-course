Today’s idea

A function gives a name to a reusable job. In Rust, fn starts a function definition, its parameters have explicit types, and -> Type tells readers and the compiler what value it returns.

We will also meet the Rust distinction between a statement (performs an action but does not produce a value) and an expression (evaluates to a value). The last expression in a function can be its return value when it has no semicolon.

Step 1 · a function with no inputs

Define it, then call it

Replace the contents of src/main.rs with this first version:

fn main() {
    say_hello();
}

fn say_hello() {
    println!("Hello from my own function!");
}

Save and run cargo run. main is the program’s entry point. It calls say_hello; that call runs the body of the second function. Rust allows the function definition to appear below its call. Function names use snake_case, like Python.

Step 2 · give a function an input

Add a typed parameter

Replace the code with this version. The function now receives a number of practice days:

fn main() {
    show_practice_days(6);
}

fn show_practice_days(days: i32) {
    println!("You practised Rust for {days} days.");
}

Run it, then change 6 to another whole number and run again. days: i32 means the parameter is named days and must be a 32-bit signed integer. Rust checks that the value at the call site has the right type.

Python’s comparable definition is def show_practice_days(days):. Rust makes the parameter type part of the function’s definition.

Step 3 · return a value

Make a function calculate

Now replace it with a function that accepts two numbers and gives their sum back:

fn main() {
    let total = add_numbers(16, 7);
    println!("Together: {total}");
}

fn add_numbers(left: i32, right: i32) -> i32 {
    left + right
}

Run it. The output should be Together: 23. The arrow -> i32 declares the return type. The last line, left + right, is an expression; without a semicolon, its value becomes the function’s result.

Try adding a semicolon after left + right and run again. Rust will explain that the function body no longer produces the promised i32. Remove the semicolon to restore the return value.

Statement or expression?

Statementlet count = 6;Creates a binding; it does not itself produce a value.
Expressioncount + 1Evaluates to a value—in this case, 7.
Expression used as the return valueleft + rightAt the end of the function, no semicolon means this value is returned.
Explicit early returnreturn total;Leaves the function immediately with that value.

A block can contain statements and finish with an expression:

let next_week = {
    let this_week = 6;
    this_week + 1
};

Here, let this_week = 6; is a statement. The final this_week + 1 is an expression, so next_week receives 7. Adding a semicolon to that final line would make the block produce no number.

Step 4 · add a decision inside a function

Return early when a target is reached

Replace the program with this version, which combines today’s functions with yesterday’s if:

fn main() {
    let total = add_numbers(16, 7);
    println!("Together: {total}");
    println!("{}", days_until_goal(total, 30));
}

fn add_numbers(left: i32, right: i32) -> i32 {
    left + right
}

fn days_until_goal(current_days: i32, goal: i32) -> i32 {
    if current_days >= goal {
        return 0;
    }

    goal - current_days
}

Run it. It should report 14 days until the goal. Change the call to days_until_goal(30, 30): the function returns early with 0. If the goal has not been reached, the final expression goal - current_days supplies the result.
